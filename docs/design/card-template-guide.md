# Card template guide

How to author a card row in `src/engine/manifest-catalog.ts` (mirrored verbatim into
`src/content/progression/base/catalogs.json5`) so it reads like a person handled a
thing, not like a database printed one.

This guide exists because of a specific failure. The first version of composed cards
measured 96–98% "distinct detail strings" across 50 harvests, and that number was worth
nothing: a footer printed the year, the era and the activity totals on every card, so two
identical cards differed as _strings_ while the player read the same card twice. Variety
is not a string property. It is a reading experience. Everything below is a rule about
what the player reads.

---

## 1. The shape of a row

Every row needs four strings, and everything else is optional:

| Field       | Required | What it is                                                                            |
| ----------- | -------- | ------------------------------------------------------------------------------------- |
| `name`      | yes      | The title. This is what the player scans.                                             |
| `one_liner` | yes      | One line under the title. Same scan, second beat.                                     |
| `subject`   | yes      | A noun phrase, used in focus lines. Never a sentence.                                 |
| `detail`    | yes      | The body. A row with no `templates` uses this verbatim.                               |
| `tags`      | yes      | Content ids. A `figure:*` tag makes the row reachable by a window naming that figure. |
| `templates` | no       | Alternative phrasings of the same card.                                               |
| `long_fire` | no       | One sentence earned by a long cook.                                                   |
| `rare`      | no       | One sentence earned by a rare card.                                                   |

**A row with no `templates` is a floor, not a bug.** It still works verbatim. Content can
be added one row at a time.

---

## 2. Slots

A `template` is one alternative phrasing of a row. Any of `name`, `one_liner` and
`detail` may carry slots; any slot left empty falls back to the row's own field.

| Slot        | Contract                                                                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `{{hour}}`  | A number, 0–23. Write it as a number a person would read: "struck with the mallet at {{hour}}". Never build a sentence that only works for one parity.      |
| `{{count}}` | An integer. Decide the grammar yourself: "you have {{count}} unbroken days" needs ≥1.                                                                       |
| `{{tie}}`   | A cased person name, or nothing. Write it so the sentence still reads if the slot is empty, or guard the template so it is only eligible when a tie exists. |

### There is no mechanical grammar checker, on purpose

A checker cannot decide whether a given sentence is grammatical English. It sees
neighbouring words, and the same neighbourhood is valid in one phrasing and invalid in
another. So instead of pretending to verify arbitrary English, the engine **pins the
finite set of authored slot usages** and requires a human to read each one.

That list is `SLOT_USAGE` in `src/engine/__tests__/card-copy.test.ts`, regenerated by a
sweep. When you add a template that uses a slot, the test fails until you have read the
new line in context and the list is updated. That is the whole review procedure. There is
no step after it.

---

## 3. Precedence

The composer resolves in this order. Getting this wrong is the most common way to make an
authored template look dead.

**Era.** An era-scoped template wins outright. If any candidate template carries
`era: 'tang'` and the life is Tang, the neutral candidates are dropped — they are not
competed with. Mixing them let the same seeded index land on the neutral template and mask
the variants, which made two eras produce byte-identical sequences.

**Rarity.** A template carrying `gate: 'uncommon'` or `gate: 'rare'` is only a candidate
when the rolled rarity is at least that rank. A gated template is how a rare card _reads_
rare, beyond the `rare` sentence.

**Brief.** If the brief shares words with a template's own copy, the matching template is
chosen. The seeded rotation only breaks ties among equally matching candidates. This is
what makes three different briefs over one window produce three genuinely different cards
instead of one card with a coin flip in it.

**Archive.** A template whose rendered `detail` is already on the bench is skipped. When
title history exists, an unseen `name` + `one_liner` pair outranks an unseen detail: the
player recognises titles across consecutive cards and does not recognise details. When
there is no title history, the detail check is the one that runs.

**Row.** The row is chosen _before_ the composer runs, because the composer can only
rotate templates inside one row. When every row of the predicted kind has its title
already on the bench, a row whose title is not held is preferred. Figure rows keep first
call regardless — a window naming Kṣitigarbha should harvest Kṣitigarbha, and repeat
suppression is a preference for the non-figure case, not a veto over the figure lane.

---

## 4. Qualifiers: `long_fire` and `rare`

A long cook and a rare card each earn one extra sentence. The row's own sentence wins.
Failing that, the composer rotates a shared six-sentence pool
(`LONG_FIRE_POOL` / `RARE_POOL` in `card-composer.ts`).

- **The pools are a fallback, not the default.** Every non-figure row now authors its own
  `long_fire` and `rare`, so the pools should be unreachable in a normal run. They stay
  because a row with no authored line still has to render, and a pool that is never used
  cannot dominate a run. `card-variety.test.ts` fails if pool-sourced lines pass 25% of a
  120-card sweep; it currently measures 0%. If you author a row, add the two lines — that
  is the expected shape now, not an optional extra.
- **Qualifiers are selected once, before rendering.** They are returned as a value, not
  drawn inside the render call. The render runs once per _candidate_ while the dedup pass
  compares templates; a draw inside it would advance the stream on every comparison and
  the same candidate would render differently each time it was inspected.
- **A card that is both long-fire and rare currently gets one qualifier, not two.** This is
  an open decision, not an accident. Check the code before assuming.

### The mechanic banlist

Composer-generated text — the shared pools, slot fills, flourishes — may not name the
bench:

> `window` · `cook` · `tier` · `bay` · `residue` · `manifest` · `batch` · `archive` · `slot`

**Whole words only**, and **authored row copy is exempt.** "Bronze floats rise in tiered
reservoirs" and a window in a wall are ordinary English that a person wrote on purpose.
The banlist targets the sentences the machine wrote, because those are the ones a player
cannot tell were made by a machine.

A test holds the pools to this list, and `card-variety.test.ts` holds the rendered output
of a long-fire sweep.

---

## 5. Ties

A tie is a person, and naming a person on every card makes every card about a person.

- **Ties may only appear through the authored `{{tie}}` slot.** Never appended, never in a
  footer. A global "Closest tie:" line is the form-letter failure in miniature.
- **Roughly a third of cards is the ceiling.** A test asserts ≤34%. Measured across three
  seeds it sits near 17%.
- **Never humanize a handle into a name.** `m-guest` is not "M Guest". If a tie has no
  resolvable display name, it is omitted: `LifeTie.name` is `null`, `strongest_tie` is
  `null`, and the card prints nothing. `id` still carries identity, so pin and lookup paths
  are unaffected. This is a hard rule — a plausible-looking invented person is worse
  than no person.

---

## 6. What was removed, and do not put it back

- **The closing footer.** Year, era, activity totals and the closest tie used to print on
  every card. Gone. `card-variety.test.ts` asserts they never return.
- **The raw id suffix on `subject`.** A "(tea)" or "(knot)" parenthetical built from a
  residue id. A raw id segment is not a word.
- **Global long-fire / rare prose.** Replaced by row-owned sentences and rotated pools.
- **A distinctness percentage as a quality bar.** If you want to measure variety, measure
  something a reader can notice: how many distinct titles a run of 24 cards touches, how
  many repeats are back-to-back. `card-variety.test.ts` does this.

---

## 7. Adding a row

1. Author the row in `src/engine/manifest-catalog.ts`.
2. Add the two new lines to `SLOT_USAGE` if it uses a slot, after reading them in context.
3. Add the same entry to `src/content/progression/base/catalogs.json5`, field for field.
   `src/content/progression/__tests__/catalogs.test.ts` asserts the mirror is exact.
4. `pnpm exec vitest run src/content/progression/__tests__/catalogs.test.ts src/engine/__tests__/card-copy.test.ts src/engine/__tests__/card-variety.test.ts`
5. Read the new card aloud in `docs/design/eval/05-composed-cards.md`. If it does not
   sound like a person handled a thing, the row is not done.

## 8. Content gaps

Everything in this list is either closed or an honest remaining gap. The first three were
the wave-1 review findings and are done.

- ~~Only `thing` rows carry variants~~ — **done.** All six `outcome` and all five `change`
  rows now carry two title variants. A 24-card run went from 6 distinct titles to 18
  (`outcome`) and 15 (`change`).
- ~~`change` rows fall back to the shared pools~~ — **done.** All 31 non-figure rows across
  the five core kinds author both qualifiers.
- ~~No normalization of rendered prose~~ — **done.** `src/engine/prose-normalize.ts` runs on
  `name`, `one_liner`, `subject` and `detail`: it trims, collapses whitespace, capitalizes
  after sentence-ending punctuation, and drops a repeated function word. See §9.
- **Era-specific templates exist for `thing` only.** The other four kinds read as a Tang
  workshop in a different year. This is still open.
- **Ten renaming templates still inherit their row's qualifier.** Most are correct —
  "The other cloak" is the same cloak, and two descriptions of one object should share
  its voice. The composer cannot tell "same object, second angle" from "different
  object, same row", so `card-variety.test.ts` prints the list rather than failing on
  it. Read it when you add a renaming template. It is what caught "Six-leaf rule",
  which is a genuinely different carpenter's rule and now overrides both its qualifiers.
- **Ties are under-used, not over-used.** 14 of 45 rows carry a `{{tie}}` template, and a
  30-card run named the tie twice. The ceiling is a third; the honest reading is that the
  slot is too thinly spread. Under-using it is the safe direction.

## 9. Re-author bad frames even though the normalizer exists

`normalizeProse` makes rendered output safe. It does not make a bad frame _good_, and a
malformed source string is a defect that happens to be masked. Two rules follow.

- **`{{hour}}` is a whole phrase, and it brings its own preposition.** The slot returns
  "in the early morning" / "at the fourth hour". So `set out at {{hour}}` renders "set out
  at at the fourth hour", and `{{hour}} you are already at the bench` renders "in the early
  morning you are already at the bench". Do not add a preposition. Do not use the slot
  where a bare adverb is wanted.
- **`{{count}}` is a duration phrase, not a bare number.** It returns "less than a moment" /
  "three long hours". So it fits `for {{count}}`, `It took {{count}}`, `by {{count}}` — and
  not `said nothing {{count}}` or `{{count}} of shoulder and rope`. Count the words you
  want, then read the frame around it.

This is why the normalizer is not a substitute for fixing the source. The stutter fix
strips the doubled `at at`; the frame is still wrong, and the next slot value that happens
not to stutter will render a sentence that means something else.

`card-prose-quality.test.ts` sweeps rendered output — 155,520 fields across every row, era,
hour, count, tie and fire mode — and fails on a lower-case sentence start, edge padding, a
doubled space, a repeated function word, or an unfilled slot. Judge template copy against
that test, not against the source string.
