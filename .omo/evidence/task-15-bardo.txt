WHAT SHIPPED
------------
Three Expo Router screens + their presentational views. The route files wire
`useSaveSlot` / `router` and delegate all rendering to pure components under
`src/ui/components/`, which keeps them trivially testable under the
test-renderer shim (see task 14's RNTL note).

- app/bardo.tsx (33 LOC) — route. Reads completed life out of save slot 1,
  computes echoes from `state.chain.karma_state.echoes` and the next eras via
  `nextErasAfter(previousEra)`, then renders BardoView. Picking an era calls
  `router.push({ pathname: '/life/start', params: { era } })`.
- app/settings.tsx (65 LOC) — route. Wires `useSaveSlot(1)` (settings + slots
  1-5) and a synchronous clipboard bridge (web also best-effort pushes to
  `navigator.clipboard`) and renders SettingsView.
- app/about.tsx (15 LOC) — route. Renders AboutView with `onBack = router.back`.
- src/ui/components/BardoView.tsx (279 LOC) — pure presentational.
- src/ui/components/SettingsView.tsx (425 LOC) — pure presentational + SlotRow.
- src/ui/components/AboutView.tsx (171 LOC) — pure presentational.

BARDO VIEW — rendered sections (all text via `bardo.*` string ids)
------------------------------------------------------------------
1. "Your life has ended" header — `bardo.life_ended_heading_sid`. Subheader is
   either `bardo.life_ended_in_era_sid` (resolves the previous era name) or the
   generic `bardo.life_ended_generic_sid` ("A life has ended.") when the era is
   unknown. (testID: bardo-screen)
2. "What carried forward" — `bardo.echoes_heading_sid`. Echoes are GROUPED by
   the four echo types (tendency, pattern_break, vow, unresolved_attachment),
   each group under its own `bardo.echo.group_*_sid` heading
   (testID: bardo-echo-group-<type>). Each echo renders a localized summary
   composed from `echo.type` + `echo.key` (tendency -> root label, vow -> kept /
   broken / declared state parsed from the `echo:vow:<name>:<state>` narrative
   sid, attachment -> subject, pattern_break -> fixed summary).
   GRACEFUL FALLBACK: zero echoes renders `bardo.no_echoes_sid`
   ("No echoes were detected. The next life begins unburdened.")
   testID: bardo-no-echoes.
3. "Choose your next life" — `bardo.next_life_heading_sid`. Lists each available
   era as a Pressable (testID: bardo-era-<id>) whose label is
   `bardo.choose_era_button_sid` formatted with the era name. `nextErasAfter`
   offers the other era after one is played; empty list (after both eras)
   renders `bardo.next_life_empty_sid` ("No further lives are available in this
   chain.") — the route then navigates to /chain-complete. testID: bardo-no-eras.
MUST-NOT (plan 359): no literal bardo imagery, no judgment by named beings.
This is functional UI only — MET.

SETTINGS VIEW — rendered sections (all text via `settings.*` string ids)
------------------------------------------------------------------------
1. Content warnings — `WARNING_CATEGORIES` renders one Pressable per category,
   per-category only (NO global "disable all" toggle). The 9 categories:
   death-of-self, death-of-family, illness-chronic-suffering,
   war-political-violence, betrayal, poverty-starvation, social-oppression,
   forced-moral-compromise, separation-from-loved-ones
   (testID: settings-warning-<id> + settings-warning-<id>-state).
2. Reduced motion — single Pressable (testID: settings-reduced-motion) toggling
   `settings.reducedMotion` via `onToggleReducedMotion`.
3. Font size — 3-step selector small / medium / large
   (testID: settings-font-<scale>); selected step styled distinctly.
4. Save slot management — slots 1-5 (testID: settings-slot-<n>), each row has
   Export (base64 code -> clipboard, disabled on empty slots), Import (reads
   clipboard, surfaces success/failure), Delete (disabled on empty slots).
   Exported code surfaced at testID settings-export-code. Toggles persist via
   `useSaveSlot().updateSettings()` / `setContentWarning()`.
5. About link (testID: settings-about-link) navigates to /about.
